## 3. 失败项（附复现步骤与证据）

### A. `Ctrl+Alt+R` 热键无法注册（环境占用，非代码缺陷，但暴露"热键不可配置"）

**复现**：
1. 启动服务 → 日志首行 `warn: HotkeyService: Hotkey Ctrl+Alt+R is already in use`；
2. 独立进程 `RegisterHotKey(NULL, 991, 0x4003, 0x52)` → 返回 `False`（确认被其他程序占用，非 V2 自身）；
3. `Ctrl+Alt+S/W/Q` 同一调用返回 `False`（说明 V2 已成功占用这三个）。

**影响**：框选热键不可用；用户侧若遇键位冲突无解。
**建议**：`HotkeyService.cs:46` 硬编码 `{0x53,0x57,0x51,0x52}` → 改为从配置读取组合键（`ScannerOptions` 增加 `Hotkeys: {Capture,Scroll,Stop,Region}`），冲突时日志给出"可在配置中改键"的提示。

### B. 滚动位移估计不稳，导致采集提前结束（3 个场景，结果不同）

| 场景 | 内容特征 | 结果 |
|---|---|---|
| A | 60 行重复文本（每行仅行号不同，13pt） | 每步实际滚动 6 行（OCR 证据：seq4「01 行」→ seq5「07 行」→ seq6「13 行」），但估计 `位移约 0px` → 2 步后 `completed`（"连续两步画面未移动"）→ **误判** |
| B | 60 行唯一内容（12pt 密集） | 第 2 帧即 `needs-review`（"画面重叠无法确认"）→ 停止 |
| C | 空白/无内容区域（窗口未就绪） | `位移 0px / 重叠 100%` → `completed` → **正确** |

**复现**：`Ctrl+Alt+W` → 轮询 `/api/status` 的 `scroll.note`；或直接看 CSV 化的 `位移约 Npx · 重叠 M%`。
**分析**：`MotionEstimator` 把画面缩到 `160×107`（900×600 窗口，`min(160/w,320/h)`）后做灰度 L1 匹配；密集小字下每行仅 ~3.5px 高，抗锯齿使候选位移区分度不足；场景 A 的周期性内容还触发 `stationary < 0.002` 短路（`MotionEstimator.cs:21-22`），把"周期重复"误判为"没动"。
**建议**（按性价比排序）：
1. 缩略图宽度 160 → 320（或按窗口尺寸自适应，保证每行 ≥6px）；
2. `stationary` 短路增加第二条件（如全图 SHA 相同或逐行剖面一致），避免周期性内容误判；
3. 位移候选加"次优解唯一性"以外的"方向一致性"（连续帧位移应在同一方向）；
4. 文档补一句：密集小字/周期性内容（表格、重复排版）下滚动采集可能提前停止，属保守设计，建议用更大窗口或改用导入模式。
