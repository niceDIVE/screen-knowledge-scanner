# 个人知识采集整理工具 —— 技术路线概况（供外部技术评审）

> **一句话定位**：单机、离线、零账号自动化的个人知识采集整理程序——把人在屏幕上看到的有价值内容（网页、聊天窗口、文档阅读器等任意窗口）低成本沉淀为可全文检索、可问答的本地知识库。
> 本文档面向技术评审：描述架构、关键算法、工程取舍、已知限制，全部为已实现内容，无规划项混入。

## 1. 定位与设计原则

**问题**：人工摘抄整理太慢；传统爬虫需要账号凭据、增加站点负载，且通常违反站点使用条款。

**三条设计底线**：
1. **默认零网络**：采集端只做本机截屏 + 本地 OCR，不产生任何额外网络请求。视觉 LLM 为显式开关（默认关），开启后所选截图会发往用户自行配置的接口——注意截图包含屏幕上的隐私内容；
2. **零依赖可部署**：目标机器无需安装运行时或构建链，全部使用 Windows 自带组件；
3. **证据链完整**：每份文本都保留原始截图，OCR 不可靠处（代码/JSON）走人工兜底清单，绝不静默出错。

**分工模型**：人负责导航（找到想收藏的内容），程序负责采集（框选区域内的自动滚动与拍照）、整理、检索。

## 2. 总体架构

```
┌─ 采集层 ─────────────────────────────────────────────────┐
│ 选区覆盖层（WinForms 半透明拖拽框选 → region.json）           │
│ 热键守护进程（RegisterHotKey 消息循环，不轮询、不劫持、不注入）  │
│ 单帧采集：GDI+ CopyFromScreen（DPI 感知）→ PNG              │
│ 滚动采集：阅读节奏滚动 + 稳定即拍 + 缺漏校验/自动回滚补拍        │
│ 环境预检：前台窗口/窗口矩形/光标在选区内                       │
└───────────────┬──────────────────────────────────────────┘
                ▼  inbox/shots/*.png ＋ inbox/text/*.md（含元数据）
┌─ 整理层 ─────────────────────────────────────────────────┐
│ OCR 双后端：Windows.Media.Ocr（系统内置）⇄ Umi-OCR HTTP 备用  │
│ 喂图 2x 放大（受 MaxImageDimension 约束）                     │
│ CJK 空格归一化 / 行序（引擎原生阅读序）                        │
│ 行级锚点对齐拼接（长且唯一行 + 归一化）+ 批次幂等哈希            │
│ 代码/JSON 启发式检测 → 人工复制清单                          │
│ （可选）视觉 LLM 二级结构化 → Markdown                      │
└───────────────┬──────────────────────────────────────────┘
                ▼  vault/scans/*.md ＋ vault/_shots/*.png
┌─ 存储与检索层 ────────────────────────────────────────────┐
│ Markdown vault（纯文件态，front-matter 元数据）              │
│ 全文检索 / 关键词问答（中文滑窗分词 + 按文件命中密度排序）        │
│ Web 控制台（TcpListener 手写 HTTP/1.1 ＋ vanilla JS 单页）   │
│ 安全：Host/Origin 校验、CSP+nosniff、路径白化、长操作异步       │
└─────────────────────────────────────────────────────────┘
```

数据流单向：**证据（截图）与文本（OCR）同时落盘 → 按批次（run）整理入库 → 知识库 → 检索**。所有状态均为文件（无数据库守护进程），任意环节可人工介入、可回滚。

## 3. 技术选型与理由

| 决策点 | 选择 | 理由 / 约束 |
|---|---|---|
| 运行时 | PowerShell 5.1 + .NET Framework | 目标机器零安装；与 WinRT / GDI+ / WinForms 互操作成本最低 |
| OCR 主后端 | Windows.Media.Ocr（WinRT） | 系统内置、离线、零成本；中文语言包通常已装 |
| OCR 备用 | Umi-OCR HTTP（PaddleOCR 系） | 主后端不可用时自动回退；解耦为 HTTP 接口可换任何 OCR 服务 |
| 截屏 | GDI+ CopyFromScreen + SetProcessDPIAware | 高 DPI 屏（实测 2560×1600@150% 缩放）必须按物理像素采集，否则截不全 |
| 本地服务 | TcpListener + 手写 HTTP/1.1 子集 | 运行环境实测裁剪了 HttpListener（PlatformNotSupportedException）；TcpListener 实测可用 |
| 前端 | vanilla HTML/JS/CSS 单页 | 离线可用、无构建链、无 CDN 依赖 |
| 知识库 | Markdown + PNG + front-matter | 纯文件态，Obsidian 等可直接接管；无数据库运维 |

## 4. 核心技术点（建议评审重点）

### 4.1 选区采集
全屏半透明覆盖层（WinForms，Opacity 0.30）+ 十字光标拖拽框选 → 物理像素矩形写入 `region.json` → 之后**所有采集（单拍与滚动）只拍该区域**；越界自动裁剪进虚拟屏；覆盖层坐标 → 物理屏幕坐标映射处理了虚拟屏原点非零（多显示器负坐标）情形。清除选区即恢复全屏。

### 4.2 阅读节奏采集模块（自动滚动的节奏控制）
输入自动化仅限滚轮事件，节奏参数外置配置，四层随机叠加：
- **步长**：每步滚动格数在 [2, 4] 均匀随机（约 250–500px；视口高约 1600px）；
- **步间停顿**：对数正态取样（区间 [250, 750] ms，右偏似阅读时间分布）；
- **读帖停顿**：以 1/10 概率追加 [1.5, 3.0] s；
- **回看动作**：1/6 概率"上滚 1 格 → 停 0.3–0.9s → 下滚 1 格"（平滑滚动应用中净位移可能非零，由缺漏校验层兜底）；
- 每格间隔 [60, 140] ms 随机。

**内容自适应**：某帧新增内容较多（≥8 行）时自动追加 0.8–1.8s 停顿——停顿与信息量正相关，长文不赶路、水帖不磨蹭。**总量上限**：单次扫描步数（默认 12）与总时长（默认 180s）双重封顶——上限比分布形状更重要。

节奏控制的目标是**以人类阅读速度采集、不增加站点负载**（避免固定间隔的机械请求模式）。**步长上限与视口高度的几何关系同时是无缺漏保证的前提（见 4.4）**，"每步不超过视口一半"为不可越过的底线。使用时请遵守目标站点的使用条款。

### 4.3 稳定即拍
每步滚动后，对**采集区域**（选区感知）做 96px 宽降采样灰度的**像素差阈值判定**：相邻采样变化率 <0.5% 即视为稳定。MD5 精确比对会漏掉小加载动画、且会被 GIF/视频/闪烁光标拖到永不稳定——故配 **4s 最长等待**，超时照拍并标记 unstable，交由缺漏校验层兜底。

### 4.4 无缺漏保证（可以重叠，不许缺漏）
四层机制：
1. **几何层 + 校准**：步长（≤500px）≪ 视口高度（1600px）⇒ 相邻两帧天然重叠 ≥2/3。滚动开始前对应用做**单格位移校准**（行剖面互相关求垂直偏移）——单格滚动过大的应用（如分页阅读器）自动降为每步 1 格；
2. **校验层（文本）**：每拍一帧，取新帧顶部**可用行**在上一帧全部行（归一化后）中查找；零命中 ⇒ 异常跳变 → 自动上滚 2×步长上限回退 → 补拍（标记 gapfix）→ 下一步重新覆盖间隙。可用行 = 剔除**首末行**（边缘截断产生乱码）+ 剔除**所有先前帧都出现的固定元素**（吸顶标题、悬浮按钮——否则真跳变永远"有命中"）+ 剔除长度 <4 的短行（"回复""展开"等重复短行会造成假命中）。**回滚补拍有次数上限（默认 3 次），超限停止并告警**，不做无限循环；
3. **校验层（图像）**：文本判定对空帧/纯图/视频帧失效——另设**像素级不动判定**：连续两次滚动后采集区域变化率 <0.5% ⇒ 到底。（早期版本用"共有行数 ≥ 新帧行数 − 1"的纯文本判定，新帧 0 行时 0 ≥ −1 恒真，会在纯图区域误终止——已废除其独立地位，仅作辅助信号；）
4. **入库层**：补扫帧在知识库中带 ⚠ 提示，人工核对衔接。

**环境预检**：每次滚动前校验前台窗口句柄与窗口矩形未变、光标仍在选区内（滚轮事件发给光标下的窗口）；变化则暂停等待恢复（60s 超时中止）。两次步进之间光标被移动过（人在操作）→ 附加停顿让出控制权。

**到底检测**：以像素级"连续两次滚动后画面不变"为准——纯图片/视频/空白区域的到底也能正确触发，不会误终止。

### 4.5 行级去重拼接（锚点对齐）
相邻帧重叠 35+ 行是**常态**（几何保证的直接结果），前后缀小窗口匹配必然失配 → 整帧重复。故采用**锚点对齐**：取上一帧末尾"长且唯一"的行（归一化后长度 ≥8、帧内唯一），在新帧**全部行**中定位（与缺漏校验同一查找路径），命中后向后延长连续匹配段，按位置切割；找不到锚点 → 保守全保留（宁重复不丢失）。归一化覆盖空白折叠、全半角标点、大小写；重复短行（"回复""展开"、时间戳）不满足锚点条件，不参与对齐。
（备选的"像素偏移对齐 + Y 坐标切割"未采用：实测本环境 WinRT 投影下 OcrLine.BoundingRect 属性访问静默失败，OCR 行缺可靠坐标；行剖面互相关已另用于单格位移校准。）
另设**批次幂等**：入库内容做归一化哈希，重复扫描同一区域不产生重复文档。

### 4.6 OCR 后处理与代码兜底
- **CJK 空格归一化**：Windows OCR 在汉字间插空格（"世 界 书"），按 `(?<=[CJK])\s+(?=[CJK])` 归一，否则全文检索失效；
- **行序**：信任引擎原生阅读序（实测 WinRT 投影下 BoundingRect 属性在 Sort-Object 脚本块中静默取 null，主动排序反而打乱顺序）；
- **代码/JSON 启发式**：单行 ASCII 双引号 ≥3、`"key"：` 键值模式、行内 `{"` ——命中任一强信号即把该帧列入"人工复制清单"（OCR 对代码不可靠，人工兜底优于静默出错）；
- **二级结构化（可选开关）**：疑似复杂帧交视觉 LLM（OpenAI 兼容接口），提示词要求逐字符转写 + 结构化输出；密钥仅从环境变量读取，绝不落盘。

### 4.7 本地 Web 控制台
- TcpListener + 手写 HTTP/1.1 子集（请求行/头解析、按字节循环读满 Content-Length、无 keep-alive）；单线程串行处理，**长操作（入库/视觉 LLM）已异步化**：触发即返回，后台进程执行，前端轮询状态文件；
- **安全**：仅绑定 127.0.0.1；Host 头校验（防 DNS rebinding）；**POST 一律校验 Origin / Sec-Fetch-Site**——Host 校验挡不住 CSRF（任意网页可向 127.0.0.1 发跨站表单 POST 且 Host 合法），跨源 POST 一律 403；响应统一 `X-Content-Type-Options: nosniff` + 严格 CSP（`default-src 'self'` 等），前端全部 textContent 渲染、无 innerHTML——OCR 文本来自网页，必须阻断存储型 XSS 调用本地 API 的路径；请求头部上限 8KB、Content-Length 严格校验（非数字/负数 → 400）、拒绝 Transfer-Encoding: chunked；文件访问统一经根目录白化函数（防路径穿越，双重编码残留只会 404/403）；静态资源纯文件名白名单；
- 功能：状态仪表（守护进程/滚动任务/选区/节奏参数）、单拍、滚动启停、入库（异步）、搜索/问答、文件浏览（md 与截图自动关联）、运行日志。

## 5. 工程踩坑实录（环境实证，供评审参考）
1. PS 5.1 将无 BOM 的 UTF-8 按 ANSI 解码 → 中文注释直接破坏语法；全部脚本强制 UTF-8 BOM。
2. WinRT `StorageFile.GetFileFromPathAsync` 在无包身份进程抛 0x80070005（UWP 文件代理拒绝）→ 改为 .NET 读字节 → InMemoryRandomAccessStream → BitmapDecoder。
3. WinRT 投影对象属性在 Sort-Object 脚本块中静默失败（排序键全 null）→ 放弃主动排序。
4. 函数内嵌套 `-match` 覆盖自动变量 `$Matches` → front-matter 解析必须先保存分组再逐行匹配。
5. HttpListener 在目标环境被裁剪（构造即 PlatformNotSupportedException）→ TcpListener 替代。
6. OCR 回退路径曾被静默 catch 掩盖 → 任何降级必须显式告警。

## 6. 已知限制与取舍
- **OCR 精度**：小字号/深底文字存在错字——结论是"可检索、可留证"，引用原文需对照截图或走视觉 LLM；代码块转写不依赖 OCR。已加喂图 2x 放大（受 OcrEngine.MaxImageDimension 约束，超长图自动降为 1x）；错字容忍检索（形近字归一表 + bigram 匹配）在路线图上，前提是先取 30–50 张人工校对样本量化 CER——OCR 错误以"形近"为主，拼音索引无价值。
- **吞吐**：采集节奏以人类阅读速度为界——定位"边读边沉淀"，不做全量归档。
- **平台**：Windows 专属（WinRT / WinForms / GDI+）。
- **热键实现**：RegisterHotKey 消息循环（标准机制，只占用注册的组合键），不使用 GetAsyncKeyState 轮询（键盘记录器典型行为，易被安全软件误标且空耗 CPU）。
- **本地数据安全**：vault 与截图为明文落盘，包含屏幕隐私内容——建议存放于 BitLocker 加密盘或加密目录。
- **Web 单线程**：请求仍串行处理（长操作已异步化），慢连接由 5s 读超时兜底。

## 7. 路线图
- RAG：知识库向量化 + 本地 LLM 问答（替换当前关键词问答）；
- 每日 digest：新增内容自动摘要成页；
- 增量监控：对已收藏源以人类频率低频轮询；
- Obsidian 集成：front-matter 分类标签与双链。

## 8. 建议评审关注点（v2 复审清单）
1. **4.4 重写后的到底判定**：像素级不动判定（连续 2 次 <0.5%）在 GIF/视频密集区域退化为"靠步数/时长上限收尾"，是否有更优雅的终止条件；
2. **4.5 锚点对齐的失败模式**：短帧、密集重复排版（表格）下锚点缺失时的重复率；是否值得引入编辑距离（≥0.9）二级匹配；
3. **4.4 校准**：行剖面互相关对平滑滚动中间帧的鲁棒性；4px 粒度是否足够；
4. **4.7**：Origin 缺失的本地非浏览器客户端被信任——是否需要升级为 token 校验；
5. **形近字归一表**的构建方式（数据来源、维护成本）与 bigram 2/3 阈值的召回/精度平衡。
