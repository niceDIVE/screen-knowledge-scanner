# OCR 准确率基线（T0）· Windows 本地 OCR vs Umi-OCR(Paddle) A/B

> 日期：2026-11-04 03:30–03:34 · 机器：本机 · 判据：去标点空白后的字符错误率 CER（Levenshtein / 参考字数）
> 数据集：`tests\ocr-bench\output\`（5 张，由 `make-bench-images.ps1` 生成，Microsoft YaHei，深/浅两种底色，10/12/13pt，含中英数标点密排）
> Ground truth 与图片同名 `.txt`，逐字对应

## 结果

| 用例 | 场景 | Windows 本地 OCR CER% | Umi-OCR Paddle CER% |
|---|---|---|---|
| dark-10pt | 深底聊天 10pt，4 行 | **22.3**（94 字错 21） | **6.4**（错 6） |
| dark-16px | 深底 12pt，3 行 | **9.3**（54 字错 5） | **3.7**（错 2） |
| light-10pt | 白底文章 10pt，3 行 | **24.7**（73 字错 18） | **4.1**（错 3） |
| light-13pt | 白底 13pt，3 行 | **18.5**（54 字错 10） | **1.9**（错 1） |
| mixed-10pt | JSON + URL + 数字混排 | **10.7**（84 字错 9） | **1.2**（错 1） |
| **总体** | 359 字 | **17.5%**（错 63） | **3.6%**（错 13） |

**结论：Umi-OCR(Paddle) 的 CER 是 Windows 本地 OCR 的 1/5 左右；两套链路都已用产品自身代码路径验证。**
`Umi-OCR` 列是通过 V2 产品链路得到的（`--Scanner:OcrEngine=umi` → `UmiOcr`），与直接打 Umi HTTP 接口的数字完全一致，说明 `Ocr.cs:42` 的集成是通的。

## 典型错法差异

| 原文 | Windows 本地 OCR | Umi-OCR |
|---|---|---|
| 预设的排版要控制 token 密度，别把正文挤掉了 | 预设的排版控制 token 密 ， 别把匹文卓了 | 预设的排版要控制token密度，别把正文挤掉了（全对） |
| 收到，我把世界书的插入点整体后移了一格，生成稳定多了 | 收至 J, 我把世界书的入点整 《 移了一恪 ， 生成定多了 | 收到，我把世界书的插入点整体后移了一格，生成稳定多了（全对） |
| {"preset_name":"深度润色","temperature":0.7,"top_p":0.95} | {"preset n a m e ． 深润色 •temperature 0 7,•top p• 9 | "preset_name"："深度润色""temperature":0.7"top_p":0.95 |
| 上面这种 JSON 记得手动复制，OCR 会认错引号和花括号 | 上面这种揭 ON 记得手动思制 ， OCR 会认错引号和花括号 | F面这种SON记得手动复制OCR会认错弓号和花活号 |

- Windows 本地 OCR 的主要问题是**丢字**（识别字数 85 < 参考 94）和**整段错乱**，JSON 行基本不可用。
- Umi-OCR 的主要问题是**形近字**（帧→顿、索→素、引→弓、括号→活号），字数不丢，检索命中率高得多。

## 可复跑

```powershell
# 1) 出图（5 张 png + 同名 gt txt）
powershell -File tests\ocr-bench\make-bench-images.ps1

# 2) 走产品链路测 Windows 本地 OCR（自动起隔离实例 8801，测完停掉并清理临时数据）
powershell -File tests\ocr-bench\run-ocr-bench.ps1 -OutMd tests\ocr-bench\result-windows.md

# 3) 换 Umi 引擎再测一遍（Umi-OCR 需先启动，HTTP 在 1224）
powershell -File tests\ocr-bench\run-ocr-bench.ps1 -Port 8802 -Engine umi -OutMd tests\ocr-bench\result-umi-v2.md

# 3') 或不动产品、直接打 Umi HTTP
powershell -File tests\ocr-bench\run-umi-bench.ps1 -OutMd tests\ocr-bench\result-umi-http.md
```

原始逐张 OCR 文本留档：`tests\ocr-bench\ocr-texts-20261104.txt`、`tests\ocr-bench\umi-raw-sample.json`。

## 建议阈值

- **CER ≤ 5%**：正文可检索，允许少数形近字错误
- **CER 5–10%**：能检索主关键词，但实体/数字/代码必须人工校对
- **CER > 10%**：知识库不可用（当前 Windows 本地 OCR 处于这一档）
